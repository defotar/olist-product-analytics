# Дашборд в Yandex DataLens

Дашборд строится из 8 CSV в папке [`marts/`](../marts). Они уже подготовлены: русские названия полей, обрезаны неполные месяцы и мелкие когорты 2016 года, есть поля для сортировки. Время — около 40 минут.

## 0. Вход

1. Открыть <https://datalens.ru> и войти аккаунтом Яндекса.
2. Если DataLens предложит создать экземпляр или организацию — согласиться, бесплатного тарифа достаточно.

## 1. Воркбук и подключение (5 минут)

1. Слева **Коллекции и воркбуки** → **Создать → Воркбук**, название `Olist — продуктовая аналитика`.
2. В воркбуке: **Создать → Подключение → Файлы**.
3. **Загрузить файлы** — выбрать все 8 CSV из папки `marts/` (лимит — 10 файлов на подключение).
4. Для каждого файла проверить сверху: кодировка **utf-8**, разделитель **Запятая**, заголовок столбцов **Да**.
5. **Создать подключение**, назвать `olist_marts`.

## 2. Датасеты (10 минут)

Для каждого из 8 файлов: **Создать → Датасет** → подключение `olist_marts` → перетащить файл в рабочую область → **Сохранить** с тем же именем, что у файла.

На вкладке **Поля** каждого датасета проверить две вещи:

- **Типы.** `Месяц` — **Дата**; `Когорта`, `Месяц после покупки`, `Срок доставки`, `Штат`, `Канал`, `Категория`, `Сегмент` — **Строка**; остальные — **Целое** или **Дробное число**.
- **Агрегация числовых полей** (столбец «Агрегация»): количества и суммы (`Заказы`, `Выручка, BRL`, `Лиды`, `Покупатели` и т. п.) — **Сумма**; проценты, средние и оценки — **Среднее**. В каждой строке файла одна точка графика, поэтому сумма и среднее дают то же значение, но без агрегации DataLens не построит график.

## 3. Чарты (20 минут)

В воркбуке: **Создать → Чарт**, выбрать датасет, сверху тип визуализации, затем перетаскивать поля в секции. После каждого чарта — **Сохранить** с указанным именем.

| № | Имя чарта | Датасет | Тип | Секции |
|---|---|---|---|---|
| 1 | Заказы | kpi_total | Индикатор | Показатель: `Заказы` |
| 2 | Выручка | kpi_total | Индикатор | Показатель: `Выручка, BRL` |
| 3 | Опоздания | kpi_total | Индикатор | Показатель: `Опоздания, %` |
| 4 | Покупают один раз | kpi_total | Индикатор | Показатель: `Покупают один раз, %` |
| 5 | Заказы по месяцам | monthly_kpi | Линейная диаграмма | X: `Месяц`; Y: `Заказы` |
| 6 | Опоздания по месяцам | monthly_kpi | Линейная диаграмма | X: `Месяц`; Y: `Опоздания, %`. Отдельный чарт — не добавлять вторую ось к чарту 5 |
| 7 | Опоздание и плохие отзывы | delay_vs_review | Столбчатая диаграмма | X: `Срок доставки`; Y: `Плохие отзывы, %`; Цвета: `Опоздание`; Сортировка: `Порядок` по возрастанию; Подписи: `Плохие отзывы, %` |
| 8 | Удержание по когортам | cohort_retention | Сводная таблица | Строки: `Когорта`; Столбцы: `Месяц после покупки`; Показатели: `Вернулись, %`; Цвета: `Вернулись, %` (градиентная заливка ячеек) |
| 9 | Опоздания по штатам | delivery_by_state | Линейчатая диаграмма | Y: `Штат`; X: `Опоздания, %`; Сортировка: `Опоздания, %` по убыванию; Подписи: `Опоздания, %`; Подсказки: `Доставлено заказов` |
| 10 | Конверсия лидов по каналам | seller_funnel | Линейчатая диаграмма | Y: `Канал`; X: `Конверсия, %`; Сортировка: `Конверсия, %` по убыванию; Подписи: `Конверсия, %`; Подсказки: `Лиды`, `Стали продавцами` |
| 11 | Категории | category_kpi | Таблица | Столбцы: `Категория`, `Выручка, BRL`, `Доля выручки, %`, `Накопленная доля, %`, `Средняя оценка`, `Опоздания, %`; Сортировка: `Выручка, BRL` по убыванию |
| 12 | Сегменты покупателей | rfm_segments | Столбчатая диаграмма | X: `Сегмент`; Y: `Покупатели`; Сортировка: `Покупатели` по убыванию; Подсказки: `Выручка, BRL` |

Цвет по умолчанию у одиночного ряда — один, его менять не нужно. В чарте 7 цвета задаются полем `Опоздание`: если DataLens выдал случайные цвета, нажать на шестерёнку секции **Цвета** и назначить «В срок» синий, «Опоздание» красный.

## 4. Дашборд (10 минут)

1. **Создать → Дашборд**, название `Olist: продуктовая аналитика`.
2. **Добавить → Заголовок**: «Olist: продуктовая аналитика маркетплейса, 2017–2018».
3. **Добавить → Чарт** — по очереди все чарты, раскладка сверху вниз:

| Ряд | Виджеты |
|---|---|
| 1 | Индикаторы 1–4 в одну строку |
| 2 | Заказы по месяцам (5) · Опоздания по месяцам (6) |
| 3 | Опоздание и плохие отзывы (7) · Опоздания по штатам (9) |
| 4 | Удержание по когортам (8) на всю ширину |
| 5 | Конверсия лидов по каналам (10) · Сегменты покупателей (12) |
| 6 | Категории (11) на всю ширину |

4. **Добавить → Текст** в самый верх, под заголовок:

> **Выводы.** 1) Опоздание — главный источник плохих отзывов: 62% отзывов 1–2★ против 9% при доставке в срок. 2) Опоздания сосредоточены в Рио-де-Жанейро и на северо-востоке и в пиковые месяцы. 3) 97% покупателей покупают один раз; недовольные возвращаются на четверть реже, но даже довольные — лишь в 2% случаев. 4) Платный поиск приводит продавцов в 3–5 раз эффективнее соцсетей и email. Код и методика: github.com/defotar/olist-product-analytics

5. **Сохранить**.

## 5. Публикация и скриншот

1. В дашборде сверху значок **⋯** (или «Поделиться») → **Поделиться** → вкладка **Публично** → включить **Публичный доступ**. Связанные объекты DataLens откроет сам — оставить отмеченными.
2. Включить **Автор дашборда**, текст «Никита Джахнаев», ссылка `https://github.com/defotar/olist-product-analytics`.
3. **Скопировать ссылку** и открыть её в окне инкогнито, чтобы убедиться, что дашборд виден без входа.
4. Скриншот: Cmd+Shift+4, затем пробел и клик по окну браузера. Сохранить в проект как `reports/figures/00_dashboard.png`.
5. Публичную ссылку прислать — она добавится в README рядом со скриншотом.

## Если что-то не так

| Проблема | Что сделать |
|---|---|
| Кракозябры вместо русских букв | В подключении выбрать кодировку **utf-8** для файла |
| Все столбцы слиплись в один | Разделитель — **Запятая** |
| «Для построения нужен показатель» | В датасете задать числовому полю агрегацию **Сумма** или **Среднее** |
| Месяцы в когортах идут M01, M10, M11, M02 | Сортировка в сводной таблице по `Месяц после покупки` по возрастанию |
| Даты по оси X выглядят как 01.01.2017 | В чарте: шестерёнка поля `Месяц` → формат «Месяц, год» |
